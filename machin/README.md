# Machin の公式

Machin の公式
$$
\pi=16\arctan\left(\frac{1}{5}\right)-4\arctan\left(\frac{1}{239}\right)
$$
について，まず組み込み `arctan` / `ATN` をそのまま使うとどうなるかを見て，その後で Maclaurin 展開にしたときの挙動を調べます．

## 組み込み `arctan` をそのまま使う場合

まず
$$
16\arctan\left(\frac{1}{5}\right)-4\arctan\left(\frac{1}{239}\right)
$$
をそのまま評価した結果を調べます．確認コードは [C-builtin.c](./code/C-builtin.c) と [bas/](./bas/) の `*-builtin.bas` で，collector は [collect_builtin.py](./code/collect_builtin.py) です．

```bash
cd /root/work/pi-repr
python3 machin/code/collect_builtin.py
```

ここで既に分かるのは，Machin の公式そのものは良い近似でも，「組み込み `arctan` を呼んでから引き算する」だけで best に届くとは限らない，ということです．そこで以下では，`arctan` 自体を Maclaurin 展開に置き換えたときに，どの計算形で best に近づくかを見ます．

### N-BASIC，N88-BASIC，Grant BASIC，F-BASIC

N88-BASIC の builtin Machin は `8.742278001516724D-08` だけ best より大きく，この点では N-BASIC と同じです．一方で Maclaurin 展開の `HIGH` 側は N-BASIC / F-BASIC よりかなり悪化し，むしろ BASIC-80 / GW-BASIC に近い振る舞いになります．

Grant BASIC では `4*ATN(1)` 自体は best の 1 ulp 上ですが，builtin Machin は best に戻ります．Maclaurin 展開では 6502 BASIC と同様に `SPLITLOW` だけが best に届きます．

FM-7 F-BASIC / FM-11 F-BASIC ともに，組み込み `ATN` をそのまま使う Machin の公式は best 不一致でした．ここでは二つをまとめて F-BASIC と書いています．

ここでは Machin の公式の Maclaurin 展開について，次の 2 つの計算形を区別します．

$$
S_N=\sum_{k=0}^{N}\frac{(-1)^k(1/5)^{2k+1}}{2k+1},\quad
T_N=\sum_{k=0}^{N}\frac{(-1)^k(1/239)^{2k+1}}{2k+1}
$$

- `SPLIT`: `S_N` と `T_N` を別々に計算して，最後に `16S_N-4T_N` を作る
- `TERM`: 各項
$$
\left(
16\frac{(-1)^k(1/5)^{2k+1}}{2k+1}
-4\frac{(-1)^k(1/239)^{2k+1}}{2k+1}
\right)
$$
をその場で足し合わせる

加算順序は次の 2 通りです．

- `LOW`: 低次から順に足す
- `HIGH`: 各 $N$ について `N,N-1,...,0` の順に足す

best は既知の最短の方法で変数に代入し，和も別の変数に代入してから比較します．Horner 形や tail correction のような手法は使いません．単純な計算形と加算順序の違いだけを見ます．

## 交代級数の誤差界による見積もり

`arctan(x)` の Maclaurin 展開
$$
\arctan(x)=\sum_{k=0}^{\infty}\frac{(-1)^k x^{2k+1}}{2k+1}
$$
は `0<x<1` で交代級数なので，$N$ 項までで打ち切ったときの誤差は「次の項以下」です．したがって
$$
\left|\arctan\left(\frac15\right)-S_N\right|
\le \frac{(1/5)^{2N+3}}{2N+3},\quad
\left|\arctan\left(\frac1{239}\right)-T_N\right|
\le \frac{(1/239)^{2N+3}}{2N+3}
$$
です．

Machin の公式全体では
$$
\left|\pi-(16S_N-4T_N)\right|
\le
\frac{16}{(2N+3)5^{2N+3}}
+
\frac{4}{(2N+3)239^{2N+3}}
$$
となります．

この upper bound がその型の精度しきい値より小さくなる最初の $N$ を，ここでは「見積もり」と呼びます．

| 形式 | 精度しきい値 | 見積もり |
| --- | --- | ---: |
| small FP | `2^-23` | 4 |
| MBF double | `2^-55` | 11 |
| BCD double | `5e-14` | 8 |
| `_Decimal64` | `5e-16` | 10 |
| IEEE 754 binary64 | `2^-52` | 10 |
| x87 80-bit extended precision | `2^-63` | 12 |
| IEEE 754 decimal128 | `5e-34` | 22 |
| IEEE 754 binary128 | `2^-112` | 23 |

この見積もりは，「tail がその型の 1 ulp 程度より十分小さくなるのはどの辺か」を見るには有用です．以下の結果表では，この見積もりを各行に並べて，実測と直接比較できるようにします．

補足:

- `_Decimal64` では `TERM` が明確に有利で，`TERMLOW` / `TERMHIGH` はどちらも `N=10` で best に届きますが，`SPLIT` は低次・高次のどちらから足しても届きません．
- `double` では見積もりは `N=10` ですが，`N<=120` でも `TERM` / `SPLIT` のどちらでも best には届きません．ただし低次から足すなら `SPLITLOW` の `+8.882e-16` が `TERMLOW` の `+1.332e-15` より良く，高次から足す側は両方とも `+4.441e-16` で同じです．
- `long double` では `TERMHIGH` と `SPLITHIGH` がどちらも見積もりどおり `N=12` で best に届き，`LOW` 側も同じ `+2.168e-19` で並びます．この系統では実質的に差がありません．
- `_Decimal128` では `TERMHIGH` と `SPLITHIGH` がどちらも `N=22` で best に届きますが，`LOW` 側は `TERMLOW` の `+1.926e-33` の方が `SPLITLOW` の `-3.081e-33` より良く，この系統では `TERM` がやや有利です．
- `__float128` では `TERM` / `SPLIT` の両方で best に届きます．ただし `LOW` 側は `TERMLOW` が `N=22`，`SPLITLOW` が `N=23` なので，わずかに `TERM` の方が早く届きます．
- `bestとの差` は `M_N - best` です．一致しなかった行は `N=120` の値との差を載せています．表示は `__float128` に変換して丸めた概数です．

## BASIC

probe は [bas/](./bas/) に置いてあります．ここではまず `^` を使う probe を基準にし，そのあと loop 版を試して，`|bestとの差|` が厳密に改善したときだけ loop に切り替えます．改善しなければ `^` のままにします．

具体的には，`^` 版 [collect_pow.py](./code/collect_pow.py) と loop 版 [collect.py](./code/collect.py) のそれぞれで

- `TERMLOW`
- `TERMHIGH`
- `SPLITLOW`
- `SPLITHIGH`

の 4 つの mode を実測し，その BASIC で最も `|bestとの差|` が小さい mode を比べます．loop 側が `^` 側より厳密に良いときだけ loop を採用し，同じか悪いなら `^` を採用します．
