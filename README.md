# 円周率の浮動小数点数表現

ここでは，数は10進表記で表します．別の基数を使うときは添字を使います．例えば，（添字のない） $5$ は10進表記で，これと等しい $101_{2}$ は2進表記です．特に断らない限り，数の10進表記は，切り捨てで書きます．桁数を増やしながら $\pi$ の10進表記を書いていくと， $3.14, 3.141, 3.1415, 3.14159, \cdots$ となります．ちなみに，四捨五入する場合は， $3.14, 3.142, 3.1416, 3.14159, \cdots$ です．

生身の人間が紙とペンで計算できることは，（おそらく）コンピュータでもできます．しかし，そこには正確さと性能のトレードオフがあります．

**方法1**：半径 $1$ の円の面積は，厳密に計算するなら $\pi$ です．Pythonなら次のとおりです．

```python
from sympy import pi
r = 1
area = pi * r**2
print(area) 
# pi
```

**方法3**：しかし，上記二つの方法で複雑な計算を行うと，時間がかかるという問題が起こります．例えば，明日の天気を今日中に予報できなくなります．そこで，計算を高速にするために，浮動小数点数というしくみが使われます． $\pi$ であれば， $3.1415$ といった有限桁の数で表すのです．Pythonなら次のとおりです．

```python
import math
r = 1
area = math.pi * r**2
print(area)
# 3.141592653589793
```

ここでは，この `3.141592653589793` のような数は，正確には何なのか，自分で設定するならどうするのか，ということについてまとめます．

---

このような話は $\pi$ に限りません．浮動小数点数の規格 IEEE 754 binary64 では，数は $(-1)^s\times(1 + f\times 2^{-52})\times 2^{e-1023}$ の形で表されます．ここで $s, f, e$ はそれぞれ， $1, 52, 11$ ビットです（全体で64ビット）．例えば $0.1$ は
$$(-1)^0 \times
\left(1 + 1001100110011001100110011001100110011001100110011010_2 \times 2^{-52}\right)
\times 2^{01111111011_2-1023}$$
となります．これは $\dfrac{3602879701896397}{36028797018963968}$ と等しく， $0.1=\dfrac{1}{10}$ とは等しくありません．この数の10進表示は無限に続きますが，およそ $0.1000000000000000056$ です（詳細は[『コンピュータでとく数学』](https://github.com/taroyabuki/comath)を参照）．

## 結論

ここでは， $\pi$ に最も近い表現可能値を **best** といいます．best とそれを得る文字数最小の方法をまとめます．表の「一致」は，best の10進表記と $\pi$ の10進表記が一致する小数点以下の桁数です．

### C言語（x86_64, GNU gcc）

| 型 | 文字数最小の best | best の値の10進表記 | 一致 | $\pi$ との差 |
| --- | --- | --- | --- | --- |
| `decimal64` | `(_Decimal64)M_PI` | **3.141592653589793** | 15 | `-2.38E-16` |
| `double` | `M_PI` | **3.141592653589793**11 | 15 | `-1.22E-16` |
| `long double` | `4*atanl(1)` | **3.141592653589793238**51 | 18 | `+5.02E-20` |
| `__float128` | `M_PIq` | **3.141592653589793238462643383279502**79 | 33 | `-8.67E-35` |
| `decimal128` | `3.141592653589793238462643383279503dl` | **3.1415926535897932384626433832795028** | 34 | `-8.42E-35` |

`_Decimal128` の文字列は，3.1415926535897932384626433832795028 の小数第34位を四捨五入したものです．

## 注意

QBasic では，式どうしをその場で比較した結果と，いったん変数に代入してから比較した結果が変わることがあります．例えば次のコードでは，`-1` （真）と `0` （偽）が出力されます．

```basic
DEFDBL A-Z
A=4*ATN(1)
B=245850922#/78256779#
PRINT A=B
PRINT 4*ATN(1)=245850922#/78256779#
```



こういうことが起こる理由は，直接比較では左右の式が比較のたびに再評価され，変数に代入された後より多い bit を持つ内部表現で比較されることがあるからです．ここでは，この混乱を避けるために，変数の値が等しい場合だけを対象とし，式をその場で比較した結果は対象としません．
